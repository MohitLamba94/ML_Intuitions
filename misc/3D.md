# ICP and Chamfer Distance for Point Clouds

Two recurring questions in 3D vision are: **how do we align two point clouds?** and **how do we measure how different they are?** Iterative Closest Point (ICP) addresses the first question, while Chamfer distance is a common answer to the second. Both rely on nearest-neighbor searches, but they use them for different purposes.

## Iterative Closest Point (ICP)

Suppose two scanners observe the same object from different poses. They produce a **source point cloud** $P = \{p_i\}_{i=1}^{N}$ and a **target point cloud** $Q = \{q_j\}_{j=1}^{M}$, where each $p_i,q_j\in\mathbb{R}^3$ is a 3D point and $N,M$ are the numbers of points. ICP tries to find a rigid transformation: a rotation $R\in\mathbb{R}^{3\times 3}$ and translation $t\in\mathbb{R}^3$ that move $P$ onto $Q$.

The difficulty is that we do not initially know which source point corresponds to which target point. ICP resolves this with an alternating loop:

1. **Match:** transform every source point using the current estimate, $Rp_i+t$, then pair it with its nearest point in $Q$.
2. **Align:** hold those pairs fixed and compute the rotation and translation that minimize their squared distances.
3. **Repeat:** rebuild the correspondences under the improved transformation and continue until the error barely changes.

If $c(i)$ is the index of the target point currently matched to source point $p_i$, the alignment step minimizes

$$
E(R,t)=\sum_{i=1}^{N}\left\|Rp_i+t-q_{c(i)}\right\|_2^2.
$$

Each term measures the squared gap between a transformed source point and its current target match. The sum $E(R,t)$ is therefore the total registration error for those correspondences. For fixed matches, the best rigid transform has a closed-form solution: subtract the centroids of the matched clouds, use an SVD of their cross-covariance to recover $R$, and then set $t$ so the centroids coincide.

The key intuition is that ICP turns one hard joint problem, **find the matches and the pose at the same time**, into two easy problems that help each other. Better matches produce a better pose; a better pose produces better matches.

However, ICP is a **local** optimizer. If the initial pose is poor, nearest neighbors may be incorrect and the algorithm can settle into the wrong alignment. In practice, ICP is usually given a coarse initialization, rejects obvious outlier matches, and stops when the improvement becomes negligible. A common point-to-plane variant minimizes distance along the target surface normals rather than full point-to-point distance; near the correct pose, it often converges faster on smooth surfaces.

## Chamfer Distance

Chamfer distance measures how closely two point sets cover one another without requiring known correspondences or equal numbers of points. Using the same point clouds $P$ and $Q$, the directed distance from $P$ to $Q$ is

$$
d(P\rightarrow Q)=\frac{1}{N}\sum_{i=1}^{N}\min_{1\le j\le M}\left\|p_i-q_j\right\|_2^2.
$$

For every source point $p_i$, the inner minimum finds its nearest target point in $Q$. The outer average then asks: **on average, how far must points from $P$ travel to reach some point in $Q$?** This is directed because it checks whether $P$ is covered by $Q$, but not whether $Q$ is covered by $P$.

The usual symmetric Chamfer distance checks both directions:

$$
d_{\mathrm{CD}}(P,Q)=
\frac{1}{N}\sum_{i=1}^{N}\min_{1\le j\le M}\left\|p_i-q_j\right\|_2^2
+
\frac{1}{M}\sum_{j=1}^{M}\min_{1\le i\le N}\left\|q_j-p_i\right\|_2^2.
$$

The first half penalizes source points that are far from the target; the second penalizes target points that the source failed to cover. For example, if $P$ contains only the left half of an object while $Q$ contains the whole object, $d(P\rightarrow Q)$ may still be small, but $d(Q\rightarrow P)$ exposes the missing right half.

Chamfer distance is popular as a loss for reconstructed or generated point clouds because nearest-neighbor matching is simple, handles different point counts, and is differentiable almost everywhere with respect to point positions. Its weakness is that matches are **not one-to-one**: many points may choose the same nearest neighbor. A dense cluster can therefore hide missing coverage or differences in sampling density. Earth Mover's Distance instead seeks a global one-to-one transport plan and better respects mass distribution, but is substantially more expensive.

ICP and Chamfer distance are closely related but not interchangeable. ICP repeatedly uses nearest neighbors to **estimate a transformation**. Chamfer distance uses nearest neighbors to **score two point sets** under their current coordinates. A common pipeline first aligns clouds with ICP and then reports Chamfer distance to measure the remaining geometric discrepancy.
